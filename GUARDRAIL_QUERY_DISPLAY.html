Guardrail Blocked Query Display

This page explains exactly how the app displays a pretty-formatted query when guardrails reject a request.

1) End-to-End Flow

Step 1: User submits a question in app.py.
Step 2: generate_mql in agent/agent.py calls the LLM and saves generated_mql.
Step 3: validate_execute runs guardrails via execute_parsed_query(...).
Step 4: On rejection, guardrails return success: false, guardrail, and error.
Step 5: UI reads query_result + generated_mql and renders formatted JSON.

2) Guardrail Failure Payload

When QueryGuardrails.validate_and_execute(...) rejects a query, it returns:

{
  "success": false,
  "error": "No index covers filter on field(s): ['company.name']...",
  "guardrail": "index_coverage",
  "field": "company.name",
  "query": "{...raw query...}"
}

generated_mql is still available because it is produced before validation.

3) Exact UI Render Condition

if (
    not query_result.get("success")
    and query_result.get("guardrail")
    and query_result.get("guardrail") != "execution"
):
    guardrail_query_preview = build_guardrail_query_preview(generated_mql)
    st.markdown("**Generated query (blocked by guardrails):**")
    st.code(json.dumps(guardrail_query_preview, indent=2, default=str), language="json")
Why exclude execution: that is a runtime/database failure after guardrails, not a guardrail rejection.

4) Query Preview Builder

build_guardrail_query_preview(generated_mql) normalizes output for display:

  • Always includes collection and query_type.
  • For aggregate: includes pipeline.
  • For find: includes filter plus optional projection, sort, limit.

This keeps the visible query concise and readable while preserving what the model generated.

5) Persistence Across Reruns

The same query preview is stored in chat history:

st.session_state.messages.append({
  "role": "assistant",
  "content": response_text,
  "trace": accumulated_trace,
  "dataframe": df_data,
  "guardrail_query": guardrail_query_preview,
})

During history rendering, if msg["guardrail_query"] exists, it is shown again with pretty JSON.

Result: users can inspect blocked queries immediately and after any later interaction.
